# Contributing

Keep changes within bounded benchmark evidence and comparability in
`docs/product-brief.md`. Do not add a hyperfine replacement, perfect
reproducibility claim, cache flusher, scheduler, hosted service, or untested
platform claim.

Run the commands in `docs/release.md` for release changes. Review the diff and
exact validation output before committing. Never put credentials, private
paths, secret values, or generated fuzz corpus files in tracked content.
